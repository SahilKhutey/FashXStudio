## 1. Architectural & Feature Evolution

Across the MVP lifecycle, FashXStudio progressed from a static mock catalog into an authenticated, consent-enforcing, personalized try-on and wardrobe platform.

### MVP 0–2: Foundation, Security & Consent
- Established clean architecture separating domain entities, ports, adapters, and use cases.
- Implemented dual-mode authentication: local HMAC JWTs for development/demo testing and JWKS verification for production.
- Built explicit, granular consent recording enforcing Indian DPDP Act 2023 requirements (`consent_records` and `consent_events`).
- Enforced default-deny authorization on all private endpoints, identifying users solely via authenticated principals.

### MVP 3–5: Discovery, Try-On Engine & Digital Closet
- Designed explainable recommendation scoring combining user taste embeddings, garment category affinity, size availability, and color harmony.
- Built the virtual try-on orchestration pipeline (`ProcessTryOnJobUseCase`) with asynchronous queuing, job states, idempotency guards, and owner-authorized artifact retrieval.
- Implemented user digital closet (`commerce_wardrobe`) supporting owned wardrobe items and saved catalog products with signed media URLs.

### MVP 6–8: Hardening, Release Safety & Optimization
- Hardened cascading account erasure (`erase_account`, `erase_biometrics`) guaranteeing zero residue across database tables and object storage keys.
- Implemented standardized product journey telemetry (`session-events`) with exact-once database deduplication.
- Refactored cosine similarity in recommendation ranking to fail mathematically closed (returning `None` for missing, unnormalized, or non-finite vectors) and dynamically reweighted scoring components without artificial neutral bias.
- Formalized `ImageTextEmbedder` protocol and strict 512-dimension vector validation.
- Added PIL-based byte decodability validation to virtual try-on inputs, failing closed before invoking upstream inference.
