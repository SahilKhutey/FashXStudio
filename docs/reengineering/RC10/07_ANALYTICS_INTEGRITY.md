# RC10-G: Analytics and Experiment Integrity

## 1. Objectives
Ensure analytical events accurately reflect real user interactions without polluting data streams with simulated runs, automated CI fixtures, or duplicate payloads.

## 2. Event Schema & Deduplication
Every client and server analytical event must specify:
- `event_id`: Unique UUID generated at point of origin.
- `schema_version`: Semantic schema version string (e.g. `1.0.0`).
- `user_id`: Pseudonymous user identifier.
- `timestamp`: UTC ISO-8601 creation timestamp.
- `event_type`: Categorized event (e.g. `product_view`, `vto_requested`, `buy_click`).
- `evidence_type`: `real`, `synthetic`, `simulated`, or `test`.

## 3. Quarantining Non-Real Data
Under [`scripts/rc10/validate_metrics.py`](file:///c:/Users/ASUS/Documents/FashXStudio/scripts/rc10/validate_metrics.py), metric aggregations filter strictly by `evidence_type == 'real'`:
- Events generated by integration tests or synthetic seed scripts are flagged as `test` or `synthetic`.
- Reporting queries ignore non-real events to prevent fabricated conversion or completion metrics.
- Missing metrics remain explicitly classified as `unknown` / `unmeasured` rather than default-filling with synthetic approximations.
