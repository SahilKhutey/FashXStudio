# RC-02 — Virtual Try-On Studio & Flow

## Architecture & Integration
The Virtual Try-On Studio ([`mobile/app/tryon/[jobId].tsx`](file:///c:/Users/ASUS/Documents/FashXStudio/mobile/app/tryon/[jobId].tsx)) manages the job polling lifecycle and result presentation.

## State Machine & Polling
1. **Job States**:
   - Initial: `queued`, `validating`.
   - Active: `preprocessing`, `inference`, `postprocessing`, `quality_check`.
   - Terminal: `completed`, `failed`, `cancelled`.
2. **Polling Mechanism**:
   - Implemented via `useJob(jobId, isFocused)` using adaptive polling intervals (`1000ms` initial, backoff up to `5000ms`).
   - Automatically pauses polling when screen loses focus to save client battery and network bandwidth.

## Mock Provider Transparency (Repository Policy Compliance)
- When the job is generated by the local mock try-on provider (`provider === "mock"`), an explicit high-contrast badge is displayed over the image:
  ```
  PREVIEW ONLY
  ```
- Mock results are never represented as genuine AI neural synthesis.

## Consumer Interactions
1. **Before/After Toggle**: Allows instant comparison between the original user reference photo and the rendered try-on result.
2. **Save Look**: Persists the try-on artifact into the user's digital closet.
3. **Realism Rating & Feedback**: 1–5 star rating with issue tags (*Fit looks unnatural*, *Color inaccurate*, *Blurry artifacts*, etc.) submitted to `/api/v1/tryon/jobs/{id}/feedback`.
4. **Failure Recovery**: On failure or quality rejection, displays clear error details and an inline *"Retry Try-On"* action.
