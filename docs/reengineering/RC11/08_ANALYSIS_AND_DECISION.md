# RC11: Pilot Analysis & Decision Framework

## 1. Decision Engine & Rules
Pilot evaluations generated by [`scripts/rc11/evaluate_pilot.py`](file:///c:/Users/ASUS/Documents/FashXStudio/scripts/rc11/evaluate_pilot.py) yield one of four outcomes:

```
                  +-----------------------------------+
                  |  Hard Stop Rule Triggered?        |
                  +-----------------+-----------------+
                                    |
                       YES          |          NO
                        +-----------+-----------+
                        |                       |
            +-----------v-----------+           |
            | HOLD_SAFETY_TRIGGERED |           |
            +-----------------------+           |
                                                |
               +--------------------------------v--------------------------------+
               | Must-Haves (M1–M5) & Should-Haves (S1–S4) Evaluation            |
               +--------------------------------+--------------------------------+
                                                |
               +--------------------------------+--------------------------------+
               |                                |                                |
       M=5/5 and S>=3/4                 M in {3,4} and S>=2             M2/M4 fail or M5<25%
               |                                |                                |
    +----------v----------+          +----------v----------+          +----------v----------+
    |  GO_REVIEW_REQUIRED |          |     FIX_AND_RERUN   |          |     PIVOT_OR_STOP   |
    +---------------------+          +---------------------+          +---------------------+
```

### Decision Definitions
- **`GO_REVIEW_REQUIRED`**:
  All 5 Must-Haves met, $\ge 3$ of 4 Should-Haves met, 0 stop rules triggered. Requires human founder and independent reviewer sign-off to proceed to open release.
- **`FIX_AND_RERUN`**:
  1 or 2 Must-Haves narrowly missed with clear technical root-cause and fix. Triggers a 2-week focused re-run with fresh participants.
- **`PIVOT_OR_STOP`**:
  M2 (Realism) or M4 (Trust) fundamentally fails, or Week-2 retention falls below 25%, indicating core value hypothesis rejection.
- **`HOLD`**:
  Incomplete telemetry, unverified vendor terms, or active safety investigations prevent a valid decision.

## 2. Review Sign-off Mandate
No metric script output alone constitutes a release authorization. The final pilot release decision requires dated signatures from the project founder and an independent reviewer.
