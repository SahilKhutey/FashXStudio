# FashXStudio — REST API Standards & Conventions

**Document ID:** `FASHX-API-001`  
**Version:** `1.0 — Execution Baseline`  
**Date:** `10 November 2026`  
**Scope:** `Phase 01.2 — Backend Architecture & API Contract Standards`  

---

## 1. General Principles

1. **Versioned Base URL:** All endpoints are mounted under `/api/v1`. Breaking changes require a major version bump (`/api/v2`).
2. **Strict HTTPS & TLS:** All communication must be encrypted via TLS 1.3 in staging and production.
3. **Stateless Authentication:** Stateless JSON Web Tokens (JWT) passed via `Authorization: Bearer <token>`.
4. **Idempotent Mutations:** State-changing operations that trigger background jobs (`POST /api/v1/vto/jobs`, `POST /api/v1/catalog-sources/{id}/imports`) require a client-generated `Idempotency-Key` header.
5. **Safe Error Details:** Responses returned to clients contain sanitized, user-actionable messages. Stack traces, raw database error strings, and internal model keys are confined to server-side structured logs.

---

## 2. Standard HTTP Request & Response Headers

### Client Request Headers
- `Authorization: Bearer <jwt_access_token>`
- `Content-Type: application/json`
- `X-Request-ID: req_uuid4` (Generated by client or injected by gateway)
- `Idempotency-Key: idemp_uuid4` (Mandatory for job submissions)
- `Accept-Language: en-IN, en;q=0.9`

### Gateway Response Headers
- `X-Request-ID: req_uuid4` (Echoed for correlation)
- `X-RateLimit-Limit: 100`
- `X-RateLimit-Remaining: 94`
- `X-RateLimit-Reset: 1762761600`

## 3. Standard Response Envelopes

### Successful Single Entity Response (`HTTP 200 / 201`)
```json
{
  "data": {
    "product_id": "prod_1082",
    "title": "Block-Print Cotton Kurta",
    "status": "published"
  },
  "meta": {
    "request_id": "req_a1b2c3d4",
    "timestamp": "2026-11-10T08:00:00Z"
  }
}
```

### Successful Paginated Collection Response (`HTTP 200`)
```json
{
  "data": [
    {"product_id": "prod_1082", "title": "Indigo Kurta"},
    {"product_id": "prod_1083", "title": "Slim Linen Shirt"}
  ],
  "pagination": {
    "total_count": 142,
    "limit": 20,
    "offset": 0,
    "has_more": true
  },
  "meta": {
    "request_id": "req_a1b2c3d4",
    "timestamp": "2026-11-10T08:00:00Z"
  }
}
```

### Standard Error Response Envelope (`HTTP 4xx / 5xx`)
```json
{
  "error": {
    "code": "IMAGE_VALIDATION_FAILED",
    "message": "This image cannot be used for virtual try-on.",
    "retryable": false,
    "details": {
      "reason": "MULTIPLE_PEOPLE_DETECTED",
      "guidance": "Please upload a photo containing only yourself."
    },
    "request_id": "req_a1b2c3d4"
  }
}
```

## 4. Universal Error Code Taxonomy

| HTTP Status | Error Code | Description / Safe Message | Retryable? |
| :--- | :--- | :--- | :--- |
| **400** | `INVALID_PAYLOAD` | Request body failed JSON schema validation. | No |
| **400** | `IMAGE_VALIDATION_FAILED`| Uploaded asset violated quality or single-subject rules.| Yes (With new image) |
| **401** | `UNAUTHORIZED` | Token missing, malformed, or expired. | Yes (After refresh/login) |
| **403** | `PERMISSION_REVOKED` | Merchant or shopper consent has been revoked. | No |
| **403** | `TENANT_ACCESS_DENIED` | Cross-tenant data access attempt blocked. | No |
| **404** | `RESOURCE_NOT_FOUND` | Requested entity does not exist or is inactive. | No |
| **409** | `CONFLICT` | Concurrent update or unique constraint violation. | Yes |
| **422** | `UNPROCESSABLE_ENTITY` | Business logic constraint failed. | No |
| **429** | `RATE_LIMIT_EXCEEDED` | Request threshold exceeded. | Yes (After backoff) |
| **500** | `INTERNAL_SERVER_ERROR` | Unexpected backend condition. | Yes |
| **503** | `SERVICE_UNAVAILABLE` | Background queue or ML provider unavailable. | Yes (Exponential backoff) |
| **504** | `PROVIDER_TIMEOUT` | GPU inference provider failed to respond in time. | Yes (Idempotent retry) |
