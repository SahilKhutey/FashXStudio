# Vector Index Configuration & Optimization

## 1. Overview
FashXStudio leverages PostgreSQL with the `pgvector` extension for efficient approximate nearest neighbor (ANN) vector retrieval.

---

## 2. Distance Metric Selection
- **Metric**: Cosine Distance (`<=>` operator in pgvector).
- **Mathematical Form**:
  $$\text{dist}_{\text{cosine}}(u, v) = 1 - \frac{u \cdot v}{\|u\|_2 \|v\|_2}$$
- Because all vectors generated by the embedding pipeline are strictly L2 normalized ($\|u\|_2 = \|v\|_2 = 1.0$), cosine distance is mathematically equivalent to scaled Euclidean (L2) distance:
  $$\|u - v\|_2^2 = 2 (1 - u \cdot v)$$
  This guarantees optimal numerical stability and retrieval ranking.

---

## 3. Index Types and Configurations

### 3.1 HNSW (Hierarchical Navigable Small World) Index
HNSW is the primary production index for sub-10ms nearest-neighbor retrieval:
```sql
CREATE INDEX idx_product_image_embeddings_hnsw
ON product_image_embeddings
USING hnsw (embedding vector_cosine_ops)
WITH (m = 16, ef_construction = 64);
```
- **Parameters**:
  - `m = 16`: Number of bidirectional links established per vector node. Offers ideal trade-off between index build time, RAM usage, and recall.
  - `ef_construction = 64`: Size of the dynamic candidate list during graph construction. Guarantees high clustering quality.
  - Runtime parameter: `SET hnsw.ef_search = 40;` to balance recall (>98%) with p95 query latency (<10ms).

### 3.2 IVFFLAT (Inverted File Flat) Index Alternative
For ultra-large catalog partitions where memory constraints necessitate lower RAM overhead:
```sql
CREATE INDEX idx_product_image_embeddings_ivfflat
ON product_image_embeddings
USING ivfflat (embedding vector_cosine_ops)
WITH (lists = 100);
```
- Requires `lists` tuning proportional to catalog volume (recommended: $\sqrt{N}$ where $N$ is catalog image count).

---

## 4. SQLite Development Fallback
In local development environments and CI pipelines running on SQLite:
- Vector columns are mapped to text via `Vector512` TypeDecorator (`database/models/base.py`).
- SQLite stores comma-separated or JSON float arrays.
- Test suites compute exact cosine similarity in Python using vectorized dot products.
