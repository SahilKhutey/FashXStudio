# Fashion Image Embedding Architecture

## 1. Overview
The Phase 06.3 Image Embedding Subsystem converts authorized merchant catalog imagery into high-dimensional numerical feature vectors. These vectors empower:
- Visual similarity retrieval (nearest-neighbor search).
- Visually related garment recommendations.
- Automated catalog deduplication and near-duplicate detection.
- Cross-modal text-to-image semantic matching.

The subsystem integrates with existing catalog acquisition, authorization (Phase 05.1), image pipeline (Phase 05.4), and catalog database (Phase 05.5) components.

## 2. End-to-End Pipeline Data Flow

```mermaid
flowchart TD
    IMG[Authorized Merchant Product Image] --> AUTH{Dynamic Permission Check: IMAGE_AI_PROCESS}
    AUTH -- Denied --> SKIP[Skip Embedding & Log Audit]
    AUTH -- Granted --> REG[Image Asset Registry & Checksum Validation]
    REG --> PRE[Image Preprocessing Pipeline]
    subgraph Preprocessing [Deterministic Preprocessing]
        PRE --> EXIF[EXIF Orientation Normalization]
        EXIF --> RGB[RGB Color Space Conversion]
        RGB --> BOUNDS[Dimension Bounds Check: 100x100 to 4096x4096]
        BOUNDS --> RESIZE[Aspect-Ratio Preserving Resize & Center Pad]
    end
    RESIZE --> ADAPTER[Model Adapter Interface: ImageEmbeddingAdapter]
    subgraph Inference [Self-Hosted Inference]
        ADAPTER --> MODEL[OpenCLIP ViT-B/32 Engine]
    end
    MODEL --> NORM[L2 Unit Normalization: ||v||2 = 1.0]
    NORM --> VAL{Vector Validation}
    VAL -- Invalid Dimension/NaN/Inf/Zero --> ERR[Quarantine Vector & Alert]
    VAL -- Valid 512-dim --> PERSIST[(PostgreSQL + pgvector)]
    PERSIST --> IDX[HNSW / IVFFLAT Vector Index]
    IDX --> RETRIEVAL[Nearest Neighbor Similarity Engine]
    RETRIEVAL --> FILTER{Visibility & Takedown Filter}
    FILTER --> RESULTS[Ranked Visually Similar Products]
```

## 3. Subsystem Architectural Components

### 3.1 Permission Enforcement (`service.py`)
Before any image data is retrieved or preprocessed, the subsystem checks the merchant/source permissions for `IMAGE_AI_PROCESS`. If this capability is revoked or absent, the pipeline halts immediately, preventing unauthorized model execution and maintaining compliance with **Rule I06**.

### 3.2 Preprocessing Engine (`preprocessing.py`)
Ensures deterministic input for deep learning inference:
- Transposes rotated EXIF data.
- Strips alpha channels and converts to standard 8-bit sRGB.
- Rejects corrupt, empty, or out-of-bound images (<100px or >4096px).
- Scales images while preserving aspect ratio, using bicubic interpolation with neutral padding to produce exact $224 \times 224$ px tensors.

### 3.3 Model Adapter Protocol (`base.py`)
Encapsulates model execution behind the `ImageEmbeddingAdapter` protocol. This provides vendor neutrality:
- `openclip_adapter.py`: Production-grade OpenCLIP ViT-B/32 adapter.
- `mock_adapter.py`: Deterministic test adapter generating normalized vectors for CI.

### 3.4 Vector Validation (`validation.py`)
Every vector generated by an adapter is subjected to strict invariants:
- Dimension equality: exactly 512 floats.
- Numerical validity: no `NaN`, `+Inf`, or `-Inf`.
- Non-zero norm: $\|v\|_2 > 0$.
- Unit normalization: $\|v\|_2 = 1.0 \pm 10^{-5}$.

### 3.5 Database & Vector Store (`database/models/catalog_embeddings.py`)
Vectors are persisted in PostgreSQL using the `pgvector` extension:
- `product_image_embeddings`: Contains the vector (`Vector512`), image asset ID, merchant ID, product ID, model identifier, version, SHA-256 hash, and active status.
- `embedding_model_registry`: Tracks registered and approved models.
- `embedding_jobs` & `embedding_batches`: Tracks asynchronous batch embedding progress, latency, and status.
- `embedding_migrations`: Tracks blue/green model transitions.

### 3.6 Nearest-Neighbor Similarity Retrieval (`retrieval.py`)
Executes cosine distance queries (`<=>`) via pgvector HNSW index. Automatically joins with catalog tables to apply:
- Visibility filtering (excludes unlisted, deleted, or suspended products).
- Takedown exclusion (excludes assets subject to active takedowns).
- Optional merchant isolation or category scoping.

## 4. Hard Boundaries & Invariants
1. **No Attribute Fabrication**: Visual embeddings do not provide ground-truth metadata regarding fabric composition, weave density, stitching quality, or sizing.
2. **Self-Hosted Privacy Boundary**: Image bytes are never transmitted to third-party public cloud endpoints or unverified SaaS services.
3. **Idempotency & Checksum Verification**: Every embedding record is keyed by the normalized image asset hash and model version. Re-runs on identical image content produce identical vectors without duplicating storage.
