# Phase 07.4.20 — Known Limitations and Phase 07.5 Scope Handoff

## 1. Overview
This document records known operational boundaries, design trade-offs, and intentional scope limits in the Phase 07.4 Virtual Try-On lifecycle implementation, establishing the explicit interface for Phase 07.5.

---

## 2. Known Limitations & Scope Boundaries

1. **Category Coverage**:
   - Supported in Phase 07.4: `tops`, `bottoms`, `one-pieces` (dresses, jumpsuits).
   - Unsupported / Gated: `footwear`, `accessories`, `headwear`, `jewelry`.
   - *Rationale*: Generative 2D diffusion models currently struggle with fine-grained spatial accuracy for jewelry and 3D fit for footwear. These categories are rejected with HTTP 422 (`unsupported_category`).

2. **Single Garment Try-On**:
   - The current lifecycle accepts exactly one garment image per job. Multi-garment layering (e.g. jacket over shirt + trousers) is slated for future multi-pass composition in Phase 08.

3. **Inbound Webhook Verification**:
   - Webhook reception architecture is defined and ready, but active operation currently defaults to bounded polling with jitter. Inbound webhook endpoint requires staging ingress DNS and provider dashboard callback configuration.

4. **Self-Hosted Inference Fallback**:
   - Self-hosted model serving (e.g. ComfyUI / Diffusers on AWS EC2 G5/G6) is intentionally disabled and blocked in `ReleaseConfig` for staging and production until Phase 08. All production inference routes through approved hosted providers (FASHN).

---

## 3. Handoff to Phase 07.5 (Quality Evaluation & Production Readiness)
With the complete, recoverable, secure lifecycle implemented in Phase 07.4, Phase 07.5 will address:
- Formal human-in-the-loop and automated visual quality evaluation datasets.
- Fine-grained artifact distortion detection (hands, face, logo preservation).
- Production SLO monitoring and alert routing.
