# Phase 07.4.19 — Performance Benchmarks and Cost Reconciliation Model

## 1. Overview
The Virtual Try-On lifecycle connects synchronous client endpoints to GPU-based asynchronous inference. This report details expected latency distributions, concurrency ceilings, and the financial cost model for commercial VTO operations.

---

## 2. Latency Budget Analysis

The total lifecycle latency $T_{\text{e2e}}$ is composed of four distinct operational phases:

$$T_{\text{e2e}} = T_{\text{queue}} + T_{\text{prep}} + T_{\text{provider}} + T_{\text{output}}$$

| Phase | Description | Expected (p50) | Target (p95) | Max Budget | Optimization Strategy |
| :--- | :--- | :--- | :--- | :--- | :--- |
| $T_{\text{api}}$ | Synchronous 202 Accepted | $45\text{ ms}$ | $110\text{ ms}$ | $200\text{ ms}$ | Async database query, non-blocking outbox insert |
| $T_{\text{queue}}$ | Queue wait until worker claim | $250\text{ ms}$ | $1.8\text{ s}$ | $5.0\text{ s}$ | Auto-scaling worker pool based on queue depth |
| $T_{\text{prep}}$ | Validation recheck & image prep | $180\text{ ms}$ | $450\text{ ms}$ | $1.2\text{ s}$ | Pre-cached input dimensions and Pillow fast decode |
| $T_{\text{provider}}$ | External GPU inference | $8.2\text{ s}$ | $18.5\text{ s}$ | $35.0\text{ s}$ | Bounded polling with jitter; adaptive interval |
| $T_{\text{output}}$ | Download, SSRF, Pillow decode, S3 PUT | $320\text{ ms}$ | $850\text{ ms}$ | $2.0\text{ s}$ | In-memory stream processing; clean JPEG write |
| **Total $T_{\text{e2e}}$** | **Complete request-to-result** | **$9.0\text{ s}$** | **$21.7\text{ s}$** | **$43.4\text{ s}$** | Meets consumer expectation ($< 30\text{ s}$) |

## 3. Cost Reconciliation Model

### Unit Economics per Successful Generation
- **Provider API Cost (FASHN v1.6)**: \$0.045 per generation.
- **AWS S3 Storage (30-day retention)**: \$0.00003 per image.
- **AWS Data Transfer Out**: \$0.0009 per image view.
- **Total Direct COGS**: $\approx \$0.046$ per try-on generation.

### Savings through Idempotency & Caching
In e-commerce mobile sessions, approximately 12–18% of user interactions involve re-trying or revisiting an identical product/photo combination. By utilizing canonical request hashing and result caching:
- Re-try requests bypass provider inference entirely.
- Estimated cost reduction: $\sim 15\%$ reduction in provider API bill.
- Client latency for cached requests drops from $\sim 10\text{ s}$ to $< 100\text{ ms}$.
