# Phase 07.4.07 — Worker Execution and Lease Management

## 1. Overview
Virtual Try-On worker tasks run outside the synchronous web request loop inside dedicated background workers (Celery / async runner). The worker is responsible for executing the pre-inference security checks, dispatching the request to the external inference provider, tracking attempt lifecycle, validating the downloaded result, and persisting output artifacts.

---

## 2. Worker Lifecycle Stages

```
[ Worker Claims Job ] (Atomic DB lease lock)
         |
         v
[ Stage 1: Validation & Authorization Recheck ]
- DPDP Consent active? (THIRD_PARTY_VTO_PROCESSING)
- Merchant rights active? (IMAGE_AI_PROCESS, VTO_PROCESS)
- Combined Phase 07.3 input image validation pass?
         |
     +---+---+
     |       |
  (Pass)   (Fail)
     |       |
     |       +-----> [ Transition to PERMISSION_BLOCKED or VALIDATION_FAILED ] (Stop)
     v
[ Stage 2: Provider Submission ]
- Check existing TryOnProviderAttempt:
    - If already SUBMITTED, resume polling
- Insert TryOnProviderAttempt (status='PREPARED' -> 'SUBMITTING')
- Dispatch HTTP POST to provider API
         |
     +---+---+
     |       |
  (Success) (Timeout / Ambiguous Error)
     |       |
     |       +-----> [ Set Attempt='UNKNOWN', Job='SUBMISSION_UNKNOWN' ] (Halt duplicate POST)
     v
[ Stage 3: Immediate Acceptance Persistence ]
- Update Attempt -> 'ACCEPTED' with provider_job_id
- Update Job -> 'SUBMITTED', record provider_job_id, provider_submitted_at
- COMMIT to DB before entering long polling
         |
         v
[ Stage 4: Polling & Result Download ]
- Bounded polling with jittered backoff
- Download output bytes over secure HTTPS (SSRF checks)
         |
         v
[ Stage 5: Output Validation & Private Storage ]
- Decode image with Pillow (bounds: 256-4096px, max 15MB, 20MP)
- Post-inference quality check (contrast, blank frame)
- Store normalized JPEG to private S3 (tryon-results/{job_id}.jpg)
- Verify S3 object via HeadObject
         |
         v
[ Stage 6: Terminal Completion ]
- Persist TryOnArtifact with SHA-256 hashes & model provenance
- Record anonymous TryOnUsage for telemetry & cost tracking
- Atomic transition Job -> 'COMPLETED' (release lease lock)
```

---

## 3. Lease Heartbeats and Stale Worker Defense

To protect against worker crashes (OOM kill, host termination) while preventing duplicate execution:
1. **Initial Lease Duration**: When claimed, `lock_expires_at` is set to $\text{now} + 120\text{ seconds}$.
2. **Periodic Heartbeat**: During active polling, workers extend the lease by 60 seconds every 30 seconds.
3. **Optimistic Locking via `transition_if_owned`**:
   Every state update must include:
   ```sql
   WHERE id = :job_id AND locked_by = :worker_id AND lock_expires_at > NOW()
   ```
   If a worker stalls and another worker claims the expired lease, the original worker's subsequent write will fail, terminating its execution safely without corrupting state.
