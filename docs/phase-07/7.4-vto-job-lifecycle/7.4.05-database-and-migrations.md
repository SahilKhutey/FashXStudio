# Phase 07.4.05 — Database Schema and Migrations Specification

## 1. Overview
The database (PostgreSQL) is the durable source of truth for the entire Virtual Try-On lifecycle. Queue messages and in-memory worker signals are purely transient delivery mechanisms. Phase 07.4 introduces durable attempt tracking, fine-grained lifecycle timestamps, cryptographic hashes, and lease-based locking to guarantee consistent execution.

---

## 2. Schema Additions

### 2.1 Table: `tryon_jobs`
The core job record is extended with lifecycle state, lease management, and idempotency tracking:

| Column | Type | Nullable | Description |
| :--- | :--- | :--- | :--- |
| `request_hash` | `VARCHAR(64)` | Yes | SHA-256 canonical hash of request parameters. Indexed for cache lookups. |
| `progress_stage` | `VARCHAR(64)` | Yes | High-level user-facing progress (e.g. `DOWNLOADING_OUTPUT`, `VALIDATING_OUTPUT`). |
| `error_code` | `VARCHAR(64)` | Yes | Normalized error code on failure. |
| `started_at` | `TIMESTAMPTZ` | Yes | Timestamp when worker first claimed the job. |
| `provider_submitted_at`| `TIMESTAMPTZ` | Yes | Timestamp when provider accepted the submission. |
| `provider_completed_at`| `TIMESTAMPTZ` | Yes | Timestamp when provider inference finished. |
| `updated_at` | `TIMESTAMPTZ` | No | Automatically updated on every state transition. |
| `expires_at` | `TIMESTAMPTZ` | Yes | Absolute job expiration timestamp. |
| `validation_policy_version` | `VARCHAR(32)` | Yes | Policy version under which input validation executed. |
| `lock_expires_at` | `TIMESTAMPTZ` | Yes | Heartbeat expiration for worker lease ownership. |

### 2.2 Table: `tryon_artifacts`
Output artifacts are linked with cryptographic hashes and model provenance:

| Column | Type | Nullable | Description |
| :--- | :--- | :--- | :--- |
| `provider` | `VARCHAR(64)` | Yes | External provider identifier (e.g. `fashn`). |
| `provider_model_version` | `VARCHAR(64)` | Yes | Model release tag (e.g. `v1.6`). |
| `source_image_sha256` | `VARCHAR(64)` | Yes | SHA-256 hash of normalized shopper input image. |
| `garment_image_sha256` | `VARCHAR(64)` | Yes | SHA-256 hash of normalized merchant garment image. |
| `output_sha256` | `VARCHAR(64)` | Yes | SHA-256 hash of final normalized output JPEG. |
| `processing_latency_ms` | `INTEGER` | Yes | Total provider inference latency in milliseconds. |

### 2.3 Table: `tryon_provider_attempts` (New)
Durable record for every outbound dispatch to an external inference provider:

```sql
CREATE TABLE tryon_provider_attempts (
    id UUID PRIMARY KEY,
    job_id UUID NOT NULL REFERENCES tryon_jobs(id) ON DELETE CASCADE,
    attempt_number INTEGER NOT NULL,
    provider VARCHAR(64) NOT NULL,
    provider_job_id VARCHAR(128),
    status VARCHAR(32) NOT NULL DEFAULT 'PREPARED',
    request_payload_json JSONB,
    response_payload_json JSONB,
    error_code VARCHAR(64),
    error_details TEXT,
    started_at TIMESTAMPTZ NOT NULL,
    completed_at TIMESTAMPTZ,
    cost_usd NUMERIC(8, 4),
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    CONSTRAINT uq_tryon_provider_attempt_job_num UNIQUE (job_id, attempt_number)
);

CREATE INDEX ix_tryon_provider_attempts_job_id ON tryon_provider_attempts(job_id);
CREATE INDEX ix_tryon_provider_attempts_provider_job_id ON tryon_provider_attempts(provider_job_id);
```

## 3. Alembic Migration: `0051_add_tryon_lifecycle_and_attempts.py`

The migration is defined in `database/migrations/versions/0051_add_tryon_lifecycle_and_attempts.py` and revisions `0050_add_tryon_input_validations`:

### Upgrade Operations
1. Adds `request_hash`, `progress_stage`, `error_code`, `started_at`, `provider_submitted_at`, `provider_completed_at`, `updated_at`, `expires_at`, `validation_policy_version`, `lock_expires_at` to `tryon_jobs`.
2. Creates index `ix_tryon_jobs_request_hash` on `tryon_jobs(request_hash)`.
3. Adds `provider`, `provider_model_version`, `source_image_sha256`, `garment_image_sha256`, `output_sha256`, `processing_latency_ms` to `tryon_artifacts`.
4. Creates table `tryon_provider_attempts` with primary key, foreign key, unique constraint, and indexes.

### Downgrade Operations
1. Drops table `tryon_provider_attempts`.
2. Drops index `ix_tryon_jobs_request_hash`.
3. Drops added columns from `tryon_artifacts`.
4. Drops added columns from `tryon_jobs`.
