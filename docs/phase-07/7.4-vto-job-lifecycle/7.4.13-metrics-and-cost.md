# Phase 07.4.13 — Operational Metrics and Cost Accounting

## 1. Overview
Virtual Try-On operations require continuous observability into queue latencies, provider execution durations, error distributions, and inference cost reconciliation. All metrics and usage logs must adhere strictly to zero-PII standards.

---

## 2. Lifecycle Latency Definitions

Every job tracks fine-grained UTC timestamps in `tryon_jobs` and `tryon_artifacts`, enabling automated breakdown of processing latencies:

```
[ created_at ]
      |
      |   T_queue = (started_at - created_at)
      v
[ started_at ]
      |
      |   T_prep = (provider_submitted_at - started_at)
      v
[ provider_submitted_at ]
      |
      |   T_provider = (provider_completed_at - provider_submitted_at)
      v
[ provider_completed_at ]
      |
      |   T_output = (completed_at - provider_completed_at)
      v
[ completed_at ]

Total End-to-End Latency: T_e2e = (completed_at - created_at)
```

| Latency Metric | Target (p50) | Target (p95) | SLO Breach Threshold |
| :--- | :--- | :--- | :--- |
| **Queue Wait ($T_{\text{queue}}$)** | $< 1.0\text{ s}$ | $< 5.0\text{ s}$ | $> 15.0\text{ s}$ |
| **Pre-inference Prep ($T_{\text{prep}}$)** | $< 0.5\text{ s}$ | $< 1.5\text{ s}$ | $> 3.0\text{ s}$ |
| **Provider Inference ($T_{\text{provider}}$)**| $8.0\text{ s}$ | $22.0\text{ s}$| $> 45.0\text{ s}$ |
| **Output Processing ($T_{\text{output}}$)** | $< 0.8\text{ s}$ | $< 2.0\text{ s}$ | $> 5.0\text{ s}$ |
| **Total End-to-End ($T_{\text{e2e}}$)** | $< 12.0\text{ s}$| $< 28.0\text{ s}$| $> 60.0\text{ s}$ |

## 3. Cost Ledger Reconciliation

Financial reconciliation operates at two distinct layers:

### 3.1 Audited Provider Attempt Record (`tryon_provider_attempts`)
- Records `provider_job_id`, `cost_usd`, `started_at`, and `completed_at`.
- Enables line-by-line reconciliation against monthly provider invoices and API credit statements.
- Prevents billing disputes by preserving external transaction references.

### 3.2 Anonymous Usage Telemetry (`tryon_usage`)
- To preserve DPDP privacy and eliminate customer tracking in analytical warehouses, aggregate usage is logged to `tryon_usage` stripped of shopper user IDs.
- Tracks daily execution volume, success/failure counts, and aggregate GPU time per garment category.
