# Phase 07.2 — Live VTO Provider Configuration and Network Controls

## 1. Overview and Core Principle

The Virtual Try-On (VTO) subsystem connects to external hosted inference providers using a strict architectural boundary:
**The core domain and workers communicate solely through provider-neutral interfaces (`TryOnAdapter` / `TryOnModelAdapterPort`). Only the provider adapter (`FashnApiAdapter`) contains vendor-specific schemas, HTTP routes, status codes, and error payloads.**

This document details the configuration schema, secrets management, network timeouts, and concurrency protections implemented in Phase 07.2.

---

## 2. Configuration Settings Schema

The configuration parameters are defined in `backend/fashx/core/settings.py` with strict environment and schema validators:

| Environment Variable | Type | Default | Staging Target | Production Target | Description |

## 3. Secrets Management (AWS Secrets Manager)

In compliance with security invariant Rule I06 and zero-plaintext-credential rules:
1. **Secrets Path Hierarchy**:
   - Development: Local development uses `.env` (git-ignored) or test credentials.
   - Staging: `/fashx/staging/tryon/fashn-api-key`
   - Production: `/fashx/prod/tryon/fashn-api-key`
2. **Access Control**:
   - The backend worker task IAM execution role is granted `secretsmanager:GetSecretValue` permission strictly scoped to its environment ARN.
   - Credentials are injected as environment variables into ECS task definitions at startup (`valueFrom: arn:aws:secretsmanager:...`).
   - Mobile clients, frontend applications, and public APIs have zero direct network or credential access to the provider.

---

## 4. Network and Client Isolation

`FashnApiAdapter` maintains two isolated HTTP clients:
1. **API Client (`_http`)**:
   - Communicates with `https://api.fashn.ai/v1`.
   - Injects `Authorization: Bearer <FASHN_API_KEY>`.
   - Configured with `connect=5.0s`, `read=15.0s`, and `request=30.0s`.
2. **Download Client (`_dl`)**:
   - Used exclusively for retrieving rendered images from CDN URLs (`https://cdn.fashn.ai/...`).
   - **Deliberately omits the `Authorization` header** to ensure API tokens are never leaked to CDN edge nodes or third-party loggers.
   - Enforces strict SSRF validation: URLs must use the `https://` scheme and resolve to the `.fashn.ai` domain hierarchy.
   - Enforces size cap: Content larger than 15 MB is immediately rejected before decoding.

## 5. Concurrency and Rate Limiting

The `FashnConcurrencyController` (`backend/fashx/infrastructure/tryon/fashn_concurrency.py`) implements:
- **Sliding-Window Rate Limiter**: Enforces `max_submissions_per_minute` (e.g. 10/min) over a 60-second sliding window. Exceeding requests receive `TryOnError("provider_unavailable", retryable=True)` so the job queue safely requeues with exponential backoff.
- **Active Prediction Concurrency Cap**: Tracks in-flight jobs. If in-flight predictions reach `max_concurrent_predictions`, new jobs are temporarily backed off rather than dropped or submitted into an overloaded vendor queue.

---

## 6. Staging and Production Safeguards

1. **Rule I08 Enforcement**:
   - In `backend/fashx/core/settings.py` (`_fail_fast`):
     - `ENV=prod` strictly forbids `TRYON_PROVIDER=mock`.
     - `ENV=prod` strictly forbids `TRYON_PROVIDER=fashn_selfhost`.
     - Validates that `FASHN_BASE_URL` uses HTTPS and timeouts are positive integers.
   - In `backend/fashx/core/release_config.py` (`validate_release_config`):
     - Staging and production both reject unapproved/unimplemented providers.
     - Production strictly requires non-mock commercial adapters with verified licenses (`assert_production_license()`).
