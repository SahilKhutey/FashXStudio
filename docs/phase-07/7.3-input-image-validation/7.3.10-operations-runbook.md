# Phase 07.3.10 — VTO Input Validation Operations Runbook

## 1. Overview
This runbook guides on-call engineers and platform operations in monitoring, diagnosing, and resolving incidents related to the Virtual Try-On Input Image Validation subsystem and time-of-use security enforcement.

---

## 3. Alert Response Runbooks

### Alert 1: `HighValidationRejectionRate` (P2)
- **Symptom**: More than 25% of submitted shopper or garment images are rejected over a 15-minute window.
- **Potential Causes**:
  1. A new mobile app release is cropping images incorrectly or failing to apply orientation tags.
  2. Mobile image picker compression is reducing resolution below 512×512 px.
  3. A new merchant catalog ingest lacked standard studio white-background images.
- **Triage Steps**:
  1. Inspect the top issue codes in Datadog/CloudWatch:
     ```text
     top(sum by (code) (rate(vto_validation_issues_total[15m])))
     ```
  2. If `IMAGE_RESOLUTION_TOO_LOW` dominates:
     - Check client app version breakdown in logs.
     - Inspect whether the client is sending thumbnails instead of full-size assets.
  3. If `BODY_REGION_NOT_VISIBLE` dominates:
     - Check if a specific garment category (e.g. `dresses`) is receiving selfie crops.
     - Verify client UI framing guide is displayed on that app version.
  4. If `GARMENT_PROCESSING_NOT_AUTHORIZED` dominates:
     - Verify if a merchant license expired or a bulk catalog sync failed to set permission codes.

---

### Alert 2: `TimeOfUseBlockedSpike` (P1)
- **Symptom**: More than 5 try-on jobs blocked at time-of-use within one hour.
- **Meaning**: The fail-closed guard in the worker intercepted a job whose authorization became invalid while waiting in the worker queue.
- **Potential Causes**:
  1. A merchant initiated a rapid emergency catalog takedown.
  2. A shopper rapidly triggered consent revocation after queuing multiple try-on jobs.
  3. Catalog sync job erroneously flipped active garments to `DELISTED`.
- **Triage Steps**:
  1. Check `tryon_input_authorization_snapshots` for recent `DENIED` results:
     ```sql
     SELECT checked_at, subject_id, permission_scope, result
     FROM tryon_input_authorization_snapshots
     WHERE result = 'DENIED'
       AND checked_at > NOW() - INTERVAL '1 hour';
     ```
  2. If caused by merchant takedown:
     - Confirm that worker correctly prevented provider dispatch (check provider billing/dashboard).
     - Inform the catalog operations team of the affected product IDs.
  3. If caused by catalog sync bug:
     - Pause automated catalog sync until the delisting trigger is investigated.

---

### Alert 3: `ValidationServiceErrorSpike` (P1)
- **Symptom**: Unhandled exceptions in `ImageInspector` or validation database writes.
- **Potential Causes**:
  1. Database pool exhaustion or lock contention on `tryon_input_validations`.
  2. S3 / Object Store timeout or connectivity loss when reading asset bytes.
- **Triage Steps**:
  1. Inspect traceback in error monitoring (Sentry):
     - If `OperationalError` / `ConnectionRefusedError`: Check PostgreSQL connection metrics.
     - If `ClientError` / `EndpointConnectionError`: Check AWS S3 endpoint status and IAM credentials.
  2. The system fails closed; no unvalidated images will reach the provider.

## 4. Routine Maintenance & Log Queries

### Find Validation Rejections for a Specific Job
```sql
SELECT
    role,
    status,
    technical_metadata,
    issues
FROM tryon_input_validations
WHERE tryon_job_id = '<JOB_UUID>';
```

### Inspect Consent Audit Trail for Shopper
```sql
SELECT
    checked_at,
    authorization_type,
    permission_scope,
    result,
    evidence_revision
FROM tryon_input_authorization_snapshots
WHERE subject_id = '<USER_UUID>'
ORDER BY checked_at DESC;
```
