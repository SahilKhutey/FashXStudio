# Phase 07.5.08 — Stuck-Job Detection, Thresholds, and Recovery Sweeper

## 1. Overview
A job is defined as "stuck" when it has remained in a non-terminal state longer than the operational threshold expected for that specific state without heartbeat or activity updates.

The `StuckJobRecoveryService` runs as a recurring background task to identify stalled jobs and take state-aware recovery actions.

---

## 2. State-Specific Stuck Thresholds (`StuckThresholds`)

| Job State | Stuck Condition Threshold | Root Cause / Diagnosis | Recovery Action |
| :--- | :---: | :--- | :--- |
| `CREATED` | $> 30\text{ seconds}$ | API server crash before validation. | Re-run validation or cancel. |
| `VALIDATING` | $> 60\text{ seconds}$ | Input inspector worker stalled. | Restart validation or fail. |
| `QUEUED` | $> 120\text{ seconds}$ | Queue capacity exhausted or message lost. | Idempotent redispatch via outbox. |
| `PROCESSING` | $\text{now} \ge \text{lease\_expires\_at}$ | Worker container terminated / crashed. | Reclaim job; reset to `QUEUED` or resume polling. |
| `SUBMISSION_UNKNOWN` | $> 120\text{ seconds}$ | Ambiguous submission awaiting reconciliation. | Trigger reconciliation query against provider API. |
| `RETRY_PENDING` | Overdue by $> 120\text{ seconds}$ | Retry scheduler or worker queue stalled. | Force-dispatch retry message. |
| `OUTPUT_VALIDATING` | $> 60\text{ seconds}$ | Image download or Pillow decode stalled. | Resume from persisted output reference. |
| `STORING_RESULT` | $> 120\text{ seconds}$ | S3 write or database commit stalled. | Verify S3 object; finalize or retry upload. |
| `CANCEL_REQUESTED` | $> 120\text{ seconds}$ | Worker cancellation confirmation stalled. | Force transition to `CANCELLED`. |

---

## 3. Recovery Sweeper Actions

The recovery sweeper inspects candidate jobs and executes targeted actions:
```python
actions = await service.scan_and_recover_due_jobs()
```

1. **`QUEUED`**: Calls `dispatcher.ensure_dispatched(job.id)` to safely republish to the broker without duplicate database writes.
2. **`RETRY_PENDING`**: If `next_retry_at <= now`, triggers immediate dispatch.
3. **`PROCESSING` (Expired Lease)**: Calls `repository.schedule_recovery(job.id)`, resetting state to `QUEUED` and clearing the expired worker lease.
4. **`SUBMISSION_UNKNOWN`**: Schedules a reconciliation query using the provider idempotency key / client reference. **Never blind re-posts.**
