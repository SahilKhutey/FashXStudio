# Phase 07.5.01 — Repository and Lifecycle Reliability Audit

## 1. Overview
Before implementing the reliability controls for Phase 07.5, this audit inspects the current repository state across the database models, API routes, workers, provider adapters, queue infrastructure, and error-handling paths. It establishes the baseline for every task (7.5.1 through 7.5.14) and classifies each as `EXISTS_AND_VERIFIED`, `EXISTS_BUT_INCOMPLETE`, `MISSING`, or `BLOCKED`.

## 4. Architectural Decisions to Preserve

1. **PostgreSQL is the Authoritative Source of Truth**: Redis and Celery deliver execution signals; losing a queue message must never lose or corrupt a job.
2. **Job and Provider Attempt States Remain Separate**: A job's state (`RETRY_PENDING`, `PROCESSING`) is distinct from an external attempt (`SUBMITTING`, `UNKNOWN`, `ACCEPTED`).
3. **Retries are Operation-Specific**: Retrying status polling or output download must not repeat a billable inference POST.
4. **Worker Recovery Resumes from Checkpoints**: Restarted workers resume from the latest durable stage rather than re-running the entire pipeline.
