## 3. Detailed Schema Alterations

### 3.1 Added Columns on `tryon_jobs`
| Column | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `version` | `INTEGER` | `1` | Optimistic locking counter. Incremented on every transition. |
| `retry_count` | `INTEGER` | `0` | Number of safe retries attempted so far. |
| `max_retries` | `INTEGER` | `3` | Maximum permitted retries for this job. |
| `next_retry_at` | `TIMESTAMPTZ` | `NULL` | Scheduled timestamp for next retry. |
| `last_error_code` | `VARCHAR(64)` | `NULL` | Normalized error code of last failure. |
| `last_error_at` | `TIMESTAMPTZ` | `NULL` | Timestamp when last failure occurred. |
| `worker_id` | `VARCHAR(255)` | `NULL` | Identifier of worker currently holding active lease. |
| `lease_token` | `UUID` | `NULL` | Unique lease token held by owning worker. |
| `lease_expires_at`| `TIMESTAMPTZ` | `NULL` | Heartbeat deadline after which lease can be reclaimed. |
| `heartbeat_at` | `TIMESTAMPTZ` | `NULL` | Timestamp of last worker heartbeat. |
| `deadline_at` | `TIMESTAMPTZ` | `NULL` | Absolute whole-job execution deadline. |
| `cancel_requested_at`| `TIMESTAMPTZ`| `NULL` | Timestamp when cancellation was requested. |
| `failed_at` | `TIMESTAMPTZ` | `NULL` | Timestamp of terminal failure. |

### 3.2 Added Table: `tryon_job_events`
Append-only audit ledger recording every state transition:
- `id` (`UUID PK`)
- `job_id` (`UUID FK -> tryon_jobs.id ON DELETE CASCADE`)
- `from_state` (`VARCHAR(50)`)
- `to_state` (`VARCHAR(50)`)
- `event_type` (`VARCHAR(50)`)
- `reason_code` (`VARCHAR(64)`)
- `actor_type` (`VARCHAR(32)` e.g. `USER`, `WORKER`, `SYSTEM`)
- `worker_id` (`VARCHAR(255)`)
- `attempt_number` (`INTEGER`)
- `metadata_json` (`JSONB DEFAULT '{}'`)
- `created_at` (`TIMESTAMPTZ DEFAULT NOW()`)

### 3.3 Added Table: `tryon_dead_letters`
Durable store for unrecoverable errors and exhausted retries:
- `id` (`UUID PK`)
- `job_id` (`UUID FK -> tryon_jobs.id ON DELETE SET NULL`)
- `source` (`VARCHAR(100)`)
- `failure_stage` (`VARCHAR(50)`)
- `error_code` (`VARCHAR(64)`)
- `error_summary` (`VARCHAR(500)`)
- `attempt_number` (`INTEGER DEFAULT 0`)
- `original_message_id` (`VARCHAR(255)`)
- `payload_reference` (`JSONB DEFAULT '{}'`)
- `status` (`VARCHAR(32) DEFAULT 'OPEN'`)
- `resolution_note` (`TEXT`)
- `resolved_by` (`VARCHAR(100)`)
- `created_at` (`TIMESTAMPTZ DEFAULT NOW()`)
- `resolved_at` (`TIMESTAMPTZ`)

## 4. Reversibility & Rollback
The `downgrade()` function cleanly drops `tryon_dead_letters`, `tryon_job_events`, and drops the added indexes and columns from `tryon_jobs`.
