# Phase 07.5.03 — Allowed Transition Matrix and Invariant Rules

## 1. Overview
The transition matrix defines every permissible jump between job states. Any attempt to execute an unlisted jump raises `InvalidJobTransition`.

---

## 2. Transition Matrix Table

| Current State | Allowed Next States | Illegal / Blocked Next States | Trigger Conditions |
| :--- | :--- | :--- | :--- |
| `CREATED` | `VALIDATING`, `CANCELLED`, `FAILED` | `QUEUED`, `PROCESSING`, `COMPLETED` | Initial ingestion; shopper cancel before validation. |
| `VALIDATING` | `QUEUED`, `FAILED`, `CANCEL_REQUESTED`, `CANCELLED` | `PROCESSING`, `COMPLETED`, `STORING_RESULT` | Pre-inference checks complete or validation failure. |
| `QUEUED` | `PROCESSING`, `CANCELLED`, `FAILED` | `COMPLETED`, `OUTPUT_VALIDATING`, `STORING_RESULT`| Worker claims lease; shopper cancels before claim. |
| `PROCESSING` | `SUBMISSION_UNKNOWN`, `RETRY_PENDING`, `OUTPUT_VALIDATING`, `CANCEL_REQUESTED`, `FAILED` | `CREATED`, `QUEUED`, `COMPLETED` (direct) | Submit timeout, transient retry, polling success, cancellation. |
| `SUBMISSION_UNKNOWN` | `PROCESSING`, `RETRY_PENDING`, `FAILED`, `CANCEL_REQUESTED` | `COMPLETED`, `QUEUED` | Reconciliation confirms provider state. |
| `RETRY_PENDING` | `PROCESSING`, `CANCELLED`, `FAILED` | `COMPLETED`, `STORING_RESULT` | Backoff delay elapsed; worker picks up job. |
| `OUTPUT_VALIDATING` | `STORING_RESULT`, `FAILED`, `CANCEL_REQUESTED` | `COMPLETED` (direct), `PROCESSING`, `QUEUED` | SSRF & Pillow decode pass or fail. |
| `STORING_RESULT` | `COMPLETED`, `FAILED`, `CANCEL_REQUESTED` | `QUEUED`, `PROCESSING`, `VALIDATING` | S3 HeadObject verified or upload failed. |
| `CANCEL_REQUESTED` | `CANCELLED`, `FAILED`, `COMPLETED` | `QUEUED`, `CREATED` | Teardown confirmed, or provider completed before cancel arrived. |
| `COMPLETED` | `EXPIRED` | `CREATED`, `QUEUED`, `PROCESSING`, `FAILED`, `CANCELLED` | **Terminal**. Only 30-day data retention expiration permitted. |
| `FAILED` | *(None)* | All states | **Terminal**. Cannot transition. |
| `CANCELLED` | *(None)* | All states | **Terminal**. Cannot transition. |
| `EXPIRED` | *(None)* | All states | **Terminal**. Cannot transition. |

---

## 3. Transition Rules and Invariants

1. **Terminal State Immutability**:
   Once a job reaches `COMPLETED`, `FAILED`, `CANCELLED`, or `EXPIRED`, it cannot be reopened or transitioned to any active state.
2. **No Skipping Verification**:
   Direct jumps such as `CREATED` $\rightarrow$ `COMPLETED` or `QUEUED` $\rightarrow$ `COMPLETED` are blocked, ensuring output validation and storage verification are never bypassed.
3. **Optimistic Version Bumping**:
   Every legal transition increments the job's `version` by 1 (`version = version + 1`).
4. **Append-Only Auditing**:
   Every state change writes a durable record to `tryon_job_events`.
