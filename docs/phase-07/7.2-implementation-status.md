## 3. Code Modifications and New Components

### A. New Modules
1. `backend/fashx/infrastructure/tryon/fashn_mapper.py`: Translates domain requests to FASHN `/run` format (`tryon-v1.6` and `tryon-max`), serializes base64 images, and parses `/status/{id}` responses.
2. `backend/fashx/infrastructure/tryon/fashn_errors.py`: Normalizes HTTP 4xx/5xx errors and vendor asynchronous payload errors into typed `TryOnError` domain exceptions.
3. `backend/fashx/infrastructure/tryon/fashn_health.py`: Provides pre-flight connectivity and credit balance checks (`check_fashn_health`) and privacy-safe structured audit logging (`log_provider_event`).
4. `backend/fashx/infrastructure/tryon/fashn_concurrency.py`: Enforces sliding-window submission rate limits and active prediction concurrency caps.
5. `tests/unit/test_fashn_live_provider.py`: 14 unit and contract tests covering configuration, mapping, error handling, health probes, concurrency limits, and end-to-end adapter polling.

### B. Modified Modules
1. `backend/fashx/core/settings.py`: Added explicit timeouts (`fashn_connect_timeout_seconds`, `fashn_request_timeout_seconds`, `fashn_read_timeout_seconds`), retry policies (`fashn_submit_max_retries=0`, `fashn_status_max_retries=3`), concurrency limits, and validation logic.
2. `backend/fashx/core/release_config.py`: Enforced stage-appropriate security invariants preventing mock adapters in production and unimplemented self-hosting in staging and production.
3. `backend/fashx/core/dependencies.py`: Forwarded new live provider settings to `FashnApiAdapter`.
4. `backend/fashx/application/ports/tryon.py`: Added `credits_used` field to `TryOnOutput`.
5. `backend/fashx/infrastructure/tryon/fashn_api.py`: Refactored to integrate mapper, error normalizer, concurrency controller, health checker, and credit accounting.
